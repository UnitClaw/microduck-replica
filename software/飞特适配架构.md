# 官方运行时换飞特舵机 · 架构分析与适配方案

> 状态：**第一版代码已写**（2026-09-18），在 fork [`UnitClaw/microduck`](https://github.com/UnitClaw/microduck) 的 `feetech` 分支，提交 `b214486`，还没上板验证。见文末 §10。
> 对象：Pollen 官方运行时 [`pollen-robotics/microduck`](https://github.com/pollen-robotics/microduck)，读的是 2026-09-16 的 `main`（`768e192`），本地 `../microduck/` 有一份。
> 舵机：飞特 HD-1910-C001，SMS/STS 系列内存表；官方是 Dynamixel XL330-M288-T。

一句话结论：**官方运行时把"跟舵机说话"这件事收在一个 Rust trait 后面，换协议只要新写一个实现，控制环、策略、安全、IPC、`robotctl` 一行不动。而且它依赖的 `rustypot` 库已经带了飞特 STS 的协议和寄存器表，包格式都不用自己写。** 真正要动脑筋的是两处：增益单位对不上（而且在 EEPROM）、IMU 不在总线上。REBOOT 飞特新固件有（0x08），见 §3.4。

## 1. 现有架构

### 1.1 进程和 crate

一个 Cargo workspace，23 个 crate，一个 crate 一个服务或工具（`docs/design/architecture.md` §1）。跟舵机有关的只有三个：

| crate             | 行数   | 干什么                                       | 跟舵机的关系                                   |
| ----------------- | ------ | -------------------------------------------- | ---------------------------------------------- |
| `duck-control`  | 4 224  | 控制核心：模型、总线、观测、策略、安全、仿真 | **协议在这里**，`bus.rs` 708 行        |
| `robotd`        | 12 463 | 守护进程：拥有串口、50 Hz 控制环、IPC        | 开总线、等舵机上电、发起校准                   |
| `robotd-params` | 5 435  | `/etc/robot/robotd.toml` 的定义            | `[bus] port` 就一个字段                      |
| `robotctl`      | 15 560 | 命令行工具                                   | `health` 看总线状态、`robot reboot-motors` |

其余 `btd`（蓝牙）、`configd`（WiFi）、`mediad`（相机）、`padd`（手柄）、`tof`、`updater` 完全不碰舵机。

### 1.2 一个接缝：`RobotIo`

`duck-control/src/io.rs`。控制环和物理世界之间**只有这一个接口**：

```rust
pub trait RobotIo {
    fn read(&mut self) -> Result<Sensors>;                 // 一次事务：15 关节 + IMU
    fn write(&mut self, targets: &JointTargets) -> Result<()>;   // 15 个目标位置
    fn set_gain(&mut self, kp: u16) -> Result<()>;         // 每关节一次写，不是每 tick
    fn set_torque(&mut self, on: bool) -> Result<()>;      // 同上
    fn reboot(&mut self, id: u8) -> Result<()>;            // Protocol 2 的 REBOOT，清硬件错误
    fn slow_sensors(&mut self) -> Result<SlowSensors>;     // 电压 + 每关节温度，1 Hz
    fn imu_stale(&self) -> ImuStale { .. }                 // 有默认实现
    fn imu_ready(&self) -> bool { .. }                     // 有默认实现
}
```

数据结构全是 SI 单位，跟协议无关：

```rust
Sensors { positions: [f64;15] /*rad*/, velocities: [f64;15] /*rad/s*/, currents_ma: [f64;15], imu: ImuData }
ImuData { gyro: [f64;3] /*rad/s 躯干系*/, gravity: [f64;3] /*单位向量，直立 = [0,0,-1]*/, quat: [f64;4] }
JointTargets { positions: [f64;15] /*rad*/ }
SlowSensors { volts: f64 /*15 颗平均*/, temps_c: [f64;15] }
```

已经有三个实现，证明这个接缝是真的能换的：

| 实现            | 文件       | 什么时候用                                     |
| --------------- | ---------- | ---------------------------------------------- |
| `DynamixelIo` | `bus.rs` | 真机，Linux                                    |
| `FakeIo`      | `io.rs`  | `robotd --fake`，全部测试跑它                |
| `RemoteIo`    | `sim.rs` | `robotd --sim`，身体在 MuJoCo 里，TCP + JSON |

设计文档原话（`docs/design/simulation.md`）："six methods, and the only place a simulator is allowed to exist"。**我们的飞特后端就是第四个实现。**

### 1.3 `DynamixelIo` 每个 tick 干什么

```text
  tick (20 ms)
    read()   一次 sync_read：ID [200, 20..24, 30..34, 10..14]，地址 124，长度 12
             ├ 槽 0 = IMU 板（ID 200）：gyro x/y/z i16 ×3 + SFLP 四元数 x/y/z 半精度 ×3 = 12 字节
             └ 槽 1..15 = 舵机：present_pwm(2) · present_current(2) · present_velocity(4) · present_position(4)
    decide   观测 → ONNX 策略 → 目标
    write()  一次 sync_write：goal_position，15 个
  每 1 s
    slow_sensors()  一次 sync_read：地址 144，长度 3 → present_input_voltage(2) + present_temperature(1)
```

单位换算（`bus.rs`，数值从原型机 `microduck_runtime` 抄来，注释说是对着硬件量的）：

| 量   | XL330 寄存器 | 换算                                                  |
| ---- | ------------ | ----------------------------------------------------- |
| 位置 | 132, i32     | `rad = 2π·raw/4096 − π`，**2048 = 0 rad** |
| 速度 | 128, i32     | `rad/s = raw × 0.229 × 2π/60`                    |
| 电流 | 126, i16     | mA，取绝对值                                          |
| 电压 | 144, u16     | 0.1 V                                                 |
| 温度 | 146, u8      | °C                                                   |

### 1.4 开机和收尾（`robotd/src/main.rs` `open_bus`）

```text
open_bus(port)
  ├ DynamixelIo::open           serialport 1 Mbps，超时 30 ms，rustypot Xl330Controller + Protocol 2
  ├ missing_servos              ping 15 个 ID
  │    └ 恰好缺 1 个 → adopt_replacement：找出厂 ID 1（先 1 Mbps，再 57600），
  │                     写 ID、写波特率、跑寄存器检查、REBOOT 清硬件错误
  ├ check_registers             EEPROM 断言并纠正：return_delay_time=0、baud_rate=3、pwm_slope=255、shutdown=52
  └ 失败 → 每秒重试，`robotctl health` 显示 "no robot on the motor bus after N attempts"

robot.enable / init（人按了才动，进程启动从不碰扭矩）
  ├ set_torque(true)
  ├ set_gain(kp)                写 P，同时把 I、D 写 0（RAM 寄存器，断电恢复出厂）
  └ interpolate_to(DEFAULT_POSITION, 2 s)   线性插值，阻塞
```

### 1.5 跟协议绑死的常量（`model.rs`）

```rust
JOINT_IDS = [20,21,22,23,24, 30,31,32,33,34, 10,11,12,13,14]   // 左腿、颈头嘴、右腿
IMU_DXL_ID = 200
BAUD_RATE = 1_000_000
FACTORY_ID = 1; FACTORY_BAUD_RATE = 57_600                       // XL330 出厂值
EXPECTED_REGISTERS = [("return_delay_time",0),("baud_rate",3),("pwm_slope",255),("shutdown",52)]
DEFAULT_POSITION = [...]                                         // 站姿，rad，训练环境 HOME_FRAME
```

`JOINT_IDS`、`DEFAULT_POSITION` 跟协议无关，直接沿用（我们配 ID 就是照这张表配的）。后四个是 XL330 的。

### 1.6 依赖：`rustypot`

`duck-control` 的 Dynamixel 实现是 [`rustypot`](https://github.com/pollen-robotics/rustypot) 1.6.0（Pollen 自家的库）。它的结构：

```text
rustypot/src
  dynamixel_protocol/   v1.rs（FF FF 包头、8 位校验和）  v2.rs（FF FF FD 00、CRC16）
  servo/
    dynamixel/  xl330.rs  mx.rs ...
    feetech/    sts3215.rs  scs0009.rs  scs0043.rs      ← 已经有飞特
    servo_macro.rs   generate_servo! 宏：给每个寄存器生成 read_x / write_x / sync_read_x / sync_write_x
```

**关键事实**：

- `v1.rs` 实现了 `SyncRead = 0x82`、`SyncWrite = 0x83`，正是飞特的指令码（Dynamixel 1.0 本身没有 0x82，这是为飞特加的）。也带 `Reboot = 0x08`、`FactoryReset = 0x06`，`Sts3215Controller::reboot(id)` 现成，舵机不回包时返回 `Ok(false)`，不报错。
- `sts3215.rs` 用 `generate_servo!(STS3215, v1, ...)` 定义了完整 STS 内存表，生成 `Sts3215Controller`，用法跟 `Xl330Controller` 一模一样：`.with_protocol_v1().with_serial_port(port)`，然后 `sync_read_present_position(&ids)`、`sync_write_goal_position(&ids, &rads)`、`sync_read_raw_data(&ids, addr, len)`。
- 位置换算 `AnglePosition` 两家共用：`rad = 2π·raw/4096 − π`，**飞特也是 4096 步一圈、2048 是中位**，控制环看到的弧度定义不变。

也就是说包格式、校验、同步读写、寄存器命名，**全都现成**。飞特官方没有 Rust SDK（只有 C/C++、Python、FD 上位机），社区另有一个 tokio 异步的 [`DoraCN/feetech-servo-sdk`](https://github.com/DoraCN/feetech-servo-sdk)（MIT，0.3.0），我们不用它：主控运行时已经依赖 rustypot，同步阻塞的模型也跟 50 Hz 控制环更合。

## 2. 两家舵机的差别，逐项

内存表对照官方 SDK `FTServo_Linux/src/SMS_STS.h`（2025-09-27 版）、`rustypot` 的 `sts3215.rs`，以及 飞特官网 doc.feetech.cn 2026 年资料：《SCS 通信协议》v1.0（2026-06-09）、《磁编码 STS 内存表手册》v1.1（2026-08-27），副本在 [`docs/飞特资料/`](../docs/飞特资料/)。三者地址一致，新手册多了指令 0x08/0x09 和几个字段的语义。

| 事项          | XL330（Protocol 2.0）                                                            | 飞特 STS/SMS（HD-1910）                                                                                                                                                                                                                                                                                                                                                   | 对适配的影响                                                                               |
| ------------- | -------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| 包格式        | `FF FF FD 00 ID LEN INSTR … CRC16`                                            | `FF FF ID LEN INSTR … CHK`，CHK = `~(ID+LEN+INSTR+参数)`                                                                                                                                                                                                                                                                                                             | rustypot v1 已实现                                                                         |
| 指令          | PING 1 / READ 2 / WRITE 3 /**REBOOT 8** / SYNC_READ 0x82 / SYNC_WRITE 0x83 | PING 1 / READ 2 / WRITE 3 / REG_WRITE 4 / ACTION 5 /**0x06 参数恢复**（把 0x09 备份的参数恢复回来，ID 除外，要先解锁；2019 版手册里这是"恢复出厂"）/ **0x08 重启**（约 800 ms，无应答，先关扭矩）/ **0x09 参数备份** / **0x0A 状态重置**（清多圈计数）/ **0x0B 位置校准**（可带设定值，STS 固件 ≥ 3.10）/ SYNC_READ 0x82 / SYNC_WRITE 0x83 | **有 REBOOT = 0x08**，跟 Dynamixel 2.0 同码，见 §3.4；0x06 / 0x09 / 0x0A 运行时不碰 |
| 波特率        | 寄存器 8，`3` = 1 Mbps，出厂 57600                                             | 寄存器 6，`0` = 1 Mbps，**出厂就是 1 Mbps**                                                                                                                                                                                                                                                                                                                       | 换新舵机不用切波特率                                                                       |
| 出厂 ID       | 1                                                                                | 1                                                                                                                                                                                                                                                                                                                                                                         | 一样，adopt 逻辑可复用                                                                     |
| 位置          | 132（读）/ 116（写），i32，4096/圈                                               | 56（读）/ 42（写），i16，4096/圈，**第 15 位是符号位**（舵机模式下 0–4095 用不到）                                                                                                                                                                                                                                                                                 | 换算一样                                                                                   |
| 速度          | 128，i32，0.229 rpm/count                                                        | 58，u16，第 15 位符号；单位由相位 18 的 BIT2 决定：**0.0146 RPM（= 1 步/秒）或 0.732 RPM（= 50 步/秒）**，手册说精度都是 0.732 RPM                                                                                                                                                                                                                                  | 换算：`rad/s = raw·2π/4096`（按 1 步/秒），台架第 5 项实测确认单位                     |
| 电流          | 126，i16，mA                                                                     | 69，u16，**6.5 mA/单位**（STS 手册）；符号位手册没写（SDK 按第 15 位），底账确认                                                                                                                                                                                                                                                                                    | 观测用不到电流，只上报                                                                     |
| 负载          | 无                                                                               | 60，u16，0.1 %，第 10 位符号                                                                                                                                                                                                                                                                                                                                              | 可选上报                                                                                   |
| 电压 / 温度   | 144 (0.1 V) / 146 (°C)                                                          | 62 (0.1 V) / 63 (°C)                                                                                                                                                                                                                                                                                                                                                     | 同一次读就带回来，**不用单独的慢事务**                                               |
| 扭矩开关      | 64                                                                               | 40：0 关 / 1 开 /**2 阻尼**（阻力由 48 转矩限制定）/ 128 中位校准                                                                                                                                                                                                                                                                                                   | 一样；阻尼模式的取舍见 §3.3                                                               |
| 位置环增益    | P 84 / I 82 / D 80，**u16，0–16383**，RAM                                 | P 21 / D 22 / I 23，**u8，0–254**，**在 EEPROM 区（5–39）**，出厂 P/D 手册标"--"（STS3215 常见 32/32），I=0；lock=1 时写入"掉电不保存"（2026-08 STS 内存表 55 原文）；P 注"比例系数(1/4)"、D 注"微分系数(1/8)"                                                                                                                                              | **单位不同，而且是 EEPROM**，见 §3.3                                                |

## 3. 适配方案

### 3.1 总体：加一个后端，不改接缝

```text
                 robotd 控制环 · 策略 · 安全 · IPC · robotctl      ← 一行不动
                                    │
                            trait RobotIo（io.rs）
          ┌──────────────┬──────────┴─────────┬──────────────┐
      DynamixelIo     FeetechIo（新）        FakeIo        RemoteIo
      bus.rs          bus_feetech.rs        io.rs         sim.rs
      rustypot v2     rustypot v1 + STS3215
      XL330 + ID200   HD-1910 ×15 + ImuSource（新）
```

新增文件：

| 文件                                | 内容                                                                                                                                                                                                                                                                                                                                                                   |
| ----------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `duck-control/src/bus_feetech.rs` | `FeetechIo`：`RobotIo` 实现 + `open` / `check_registers` / `missing_servos` / `adopt_replacement` / `present_positions` / `interpolate_to`（跟 `DynamixelIo` 同名同签名，`robotd` 的 `open_bus` 才能不改逻辑只改类型）                                                                                                                           |
| `duck-control/src/imu_source.rs`  | `trait ImuSource { fn latest(&self) -> Option<ImuData>; fn ready(&self) -> bool }` + `Bno085I2c` 实现（自己的线程 100 Hz 读 I2C，控制环只取最新一帧，不阻塞）                                                                                                                                                                                                      |
| `duck-control/src/model.rs`       | 加`FEETECH_EXPECTED_REGISTERS`、`FEETECH_FACTORY_ID`；`JOINT_IDS`、`DEFAULT_POSITION` 不动                                                                                                                                                                                                                                                                     |
| `robotd-params/src/lib.rs`        | `[bus]` 加 `protocol = "dynamixel2" \| "feetech-sts"`（默认 dynamixel2，上游行为不变）和 `[bus.feetech]`（`p_scale`、`direction` 表、`imu = "bus" \| "bno085-i2c"`）                                                                                                                                                                                         |
| `robotd/src/main.rs`              | `open_bus` 按 `protocol` 选 `DynamixelIo` 或 `FeetechIo`；`type BusIo = DynamixelIo` 改成 `enum BusIo { Dynamixel(..), Feetech(..) }` 手写委托。**不能用 `Box<dyn RobotIo>`**：`open_bus` / adopt / `run_init` 调的 `missing_servos`、`adopt_replacement`、`check_registers`、`interpolate_to` 都不在 trait 里，`Safety<T>` 也是泛型 |
| `robotctl`                        | `health` 多显示一行协议名；`robot reboot-motors` 不改（飞特有 0x08，§3.4）                                                                                                                                                                                                                                                                                        |

放哪：fork 一份 `pollen-robotics/microduck`，分支 `feetech`，改动全部收在上面这几处，配置默认值不变，**将来能作为 PR 提回上游**（设计文档把这个接缝定义为唯一允许换实现的地方）。

### 3.2 每个 tick 的映射

```text
DynamixelIo                                   FeetechIo
sync_read [200,15 ID] @124 len 12      →      sync_read [15 ID] @56 len 15
  IMU 块 + pwm/current/vel/pos                  56 pos(2) 58 speed(2) 60 load(2) 62 volt(1) 63 temp(1)
                                                64 (1) 65 status(1) 66 moving(1) 67-68 (2) 69 current(2)
                                              + imu_source.latest()  →  Sensors.imu
sync_write goal_position @116 len 4    →      sync_write goal_position @42 len 2
slow_sensors: sync_read @144 len 3     →      不发新事务，从上一 tick 的块里取 62/63（缓存）
```

一次读把位置、速度、电压、温度、状态、电流全带回来，`slow_sensors` 变成零成本。总线时间：15 颗 × (6 + 15) 字节 ≈ 315 字节，1 Mbps 下约 3.2 ms 加应答间隔；写 15 × 3 + 8 ≈ 53 字节 ≈ 0.5 ms。**20 ms 的 tick 里绰绰有余**，比 XL330 那版（16 个设备）还省。

换算：

```rust
positions[j]  = 2π·(raw & 0x7FFF)/4096 − π        // 同 AnglePosition；舵机模式下不会出现符号位
velocities[j] = sign15(raw) · 2π/4096              // 步/秒 → rad/s
currents_ma[j]= sign15(raw) · CURRENT_MA_PER_UNIT   // HD-1910 的单位待查，先按 STS3215 的 6.5
volts         = 15 颗 0.1 V 读数的平均，0 值剔除（同 XL330 版）
temps_c[j]    = raw
```

### 3.3 增益：唯一要标定的东西，而且飞特的增益在 EEPROM

`set_gain(kp: u16)` 的 `kp` 是 XL330 的 P。`robotd-params` 里 `gain = 200` 是主参数，站立时乘 `standing_gain_ratio = 0.8` → 160，倒地放软到 `gain_limp = 50`（`limp_fall_pose_gain = 160`）。`Safety` 记住上次写的值，值不变不重写；但走 ↔ 站 ↔ 倒地每次切换都会写一轮，15 颗 × 3 字节。

飞特的 P 是 0–254 的一个字节，物理意义（每单位误差出多少 PWM）不同，**不能直接写进去**；更麻烦的是 **21/22/23 在 EEPROM 区**，照 XL330 的写法每次切状态都磨一次 EEPROM。

方案：

- **锁着写**。2026-08 STS 内存表 55 的原文："写 1 打开写入锁，写入 EPROM 地址的值掉电不保存"，也就是写入被接受、只是不落盘，正好就是 XL330 的 RAM 语义 → `set_gain` 不解锁直接写 P，零磨损，重启后回到 EEPROM 值也跟 `reboot` 契约一致。"立即生效"手册没明说，**待查第 3 条在台架看一眼**。
- **阻尼模式不是 Limp 的替代**。扭矩开关 40 写 2 = 阻尼输出、阻力由 48 定，看着像"放软"，但上游 `LimpFall::Limp` 的定义是"低增益、目标位置钉在当前位置、仍保持姿态"，注释明说不能松掉，否则头砸地、下一阶段没有姿态可 ramp。所以 `gain_limp` 还是走改 P；阻尼模式只在"彻底放手"（`robot disable` 之类）可考虑，而且 rustypot 的 `torque_enable` 是 bool，写 2 得 `write_raw_data`，SMS 表还没有这个值，HD-1910 有没有要台架验。
- 验证不成立的退路：P 只在装机时用 FD 设一次，运行中的"放软"改用 SRAM 的 `torque_limit`(48)：`set_gain(50)` 映射成把扭矩上限降到一个比例。
- 换算：`p = clamp((kp × p_scale).round(), 1, 254)`，`p_scale` 放 `[bus.feetech]`，台架标定：同一颗关节、同样的阶跃，调飞特的 P 直到响应跟 XL330 kP=200 时接近。
- **D 不清零**。XL330 版把 I、D 写 0 是因为它们出厂就是 0；飞特出厂 D=32 是厂家整定的一部分，320:1 的减速比去掉 D 可能振荡。先保留出厂 D/I，只动 P。
- 模式 4（纯位置 PD）下 P/D 的量纲和模式 0 未必一样，标定要在我们实际跑的模式下做。

这一项做不准的后果不是不能动，是**步态跟训练时不一样**，所以放在台架验收里，而且策略本来就要按 HD-1910 重训（[训练前数据清单](../docs/HD-1910训练前数据清单.md)）。

### 3.4 REBOOT：飞特新固件有，0x08

`RobotIo::reboot(id)` 在 XL330 上是 Protocol 2 的 REBOOT，用来清 `shutdown` 掩码锁住的硬件错误（过载、过热）。`io.rs` 对它的契约：**舵机回来时扭矩是关的、RAM 寄存器回到 EEPROM 默认值，增益由调用方重写**；`robotd` 收到 `reboot-motors` 先 `set_torque(false)`，做完把状态机置 `Limp`。

飞特 2026-06 版《SCS 通信协议》§4.12：**重启指令 0x08，"重启舵机"，无应答帧，重启时间约 800 ms，备注"重启前先关闭扭矩开关"**。跟 Dynamixel 2.0 的 REBOOT 同码同义。之前这份文档和两轮评审都写"飞特没有 REBOOT"，依据是 2019 版手册和 SDK 头文件，都过时了。其它几条容易混的：

| 指令              | 2026-06 手册                                                     | 结论                             |
| ----------------- | ---------------------------------------------------------------- | -------------------------------- |
| `0x06` 参数恢复 | 恢复 0x09 备份的参数，ID 除外，先解锁 EEPROM                     | 运行时不碰                       |
| `0x09` 参数备份 | 备份当前参数                                                     | 装机调好后用 FD 备份一次，值得做 |
| `0x0A` 状态重置 | 重置舵机圈数                                                     | 运行时不碰                       |
| `0x0B` 位置校准 | 无参数 = 当前位置校为中位；带参数 = 校为设定值；STS 固件 ≥ 3.10 | 装机校零用。**HD-1910 只能走这个**：扭矩开关写 128 实测不生效（2026-09-20，解锁、扭矩关着也不行，偏移不变），跟手册里 HLS ≥3.43 一样 |

`FeetechIo::reboot(id)` 实现为：扭矩 0 → `controller.reboot(id)`（rustypot v1 现成的 0x08，舵机不回包只返回 `Ok(false)`，不报错）→ **立即返回**。不等待、不 ping、不读 65：`Safety::reboot_motors` 是在控制环的 tick 里逐颗调用的，一颗等 1 s，15 颗就卡控制环 15 s；65 还有位只记 error 日志，跟 XL330 版一样。等待和 ping 放到 `adopt_replacement`（上游 `REBOOT_SETTLE` 是 500 ms，飞特约 800 ms，**要单独设 ≥ 1 s**）和台架。回来时扭矩关是手册说的；"锁着写的 P 回到 EEPROM 值"是推断（手册只说"掉电不保存"，软重启没提），待查第 3 条一起验，验过了才算满足契约。`robotctl robot reboot-motors` 一字不改。`adopt_replacement` 保留 reboot 步，理由不是 XL330 那个 alert 位（飞特没有），而是**验证新写的 ID 过了复位还在**，锁没解开的话这一步就露馅。

台架第 8 项验：手堵一颗触发过载（65 BIT5），reboot 后 1 s ping 通、65 清零、ID 保留。HD-1910 固件版本（地址 0/1）先记下来，0x08 是不是所有版本都支持，手册没写。

### 3.5 IMU 不在总线上

XL330 版的 IMU 是 `imu_to_dxl` 板挂在总线 ID 200，跟舵机一次读回来。飞特这条线上暂时没有它（小板固件还没写），躯干 IMU 两条路线并行（[调试记录](../调试记录.md)）：

|                          | A ·`imu_to_dxl` 小板                                                                        | B · BNO085 直飞主板 I2C                                |
| ------------------------ | ---------------------------------------------------------------------------------------------- | ------------------------------------------------------- |
| 接进`FeetechIo` 的方式 | 小板固件按飞特协议应答 ID 200，读 56 处一个自定义块 → 加回同一次 sync_read（ID 列表前插 200） | `ImuSource` 线程 100 Hz 读 I2C，`read()` 取最新一帧 |
| 现在能做                 | 要先写 STM32 固件                                                                              | 买块模块、i2c3 上`i2cdetect` 看到 0x4A 就能开始       |
| 代码位置                 | `bus_feetech.rs` 里分支                                                                      | `imu_source.rs`                                       |

`ImuData` 的定义不变：gyro（躯干系 rad/s）、gravity（单位向量，直立 `[0,0,-1]`）、quat（躯干→世界）。BNO085 直接给融合后的四元数和陀螺，`SflpDecoder` 那套 mount 旋转、中值滤波、`ready()` 门槛照搬一份成 `Bno085Decoder`。**方案 B 先做**，A 等固件。

`FeetechIo::read()` 的 IMU 部分：`imu_source.latest()` 拿不到就沿用上一帧并计 `imu_stale`，跟 XL330 版"板子回了同一块"的语义对齐，`imu_ready()` 直接转发。

**两条路都保留，配置选一条**（`[bus.feetech] imu = "bus" | "bno085-i2c"`），线程模型不一样：

```text
imu = "bus"          A · 小板挂总线 ID 200
                     一个线程。sync_read 的 ID 列表前面插 200，IMU 块跟 15 颗舵机一次读回，
                     形状跟官方 XL330 版完全一样，只是包格式换成飞特的。

imu = "bno085-i2c"   B · BNO085 模块直飞主板 pin 3/5
                     两个线程。
                       控制环   50 Hz   sync_read 舵机 → 取 IMU 最新一帧 → 策略 → sync_write
                       IMU      100 Hz  读 I2C（SH-2 报文）→ 换算成 ImuData → 写进共享槽（Mutex 或 ArcSwap）
                     read() 只取槽里最新一帧，不等 I2C；拿不到沿用上一帧并计 imu_stale。
```

B 单开线程的理由：IMU 100 Hz 和控制环 50 Hz 节奏不同；I2C 卡住（线松、掉电）不能拖住舵机的 tick；SH-2 报文要拆包、管序号，不该塞进 20 ms 的 tick 里。对上层两条路一样，`Sensors.imu` 都是同一个 `ImuData`，策略看不出区别。

**评审后补充（2026-09-17）**

方案 B（BNO085 直飞）：

- 四元数别复用 SFLP 的解码：`SflpDecoder` 只拿 x/y/z，`w = √(1−|v|²)` 默认 w ≥ 0；BNO085 直接给 real 分量、可为负，四个分量直接用，再按主控约定（body→world、Z 向上、重力 = R⁻¹·[0,0,−1]）转换。Game Rotation Vector 是 ENU、Hamilton 约定，跟主控一致，但 mount 四元数要按模块贴装朝向重新推，三姿态静置（直立 / 前倾 90° / 侧躺）验收。
- `imu_stale` 在 trait 里默认返回空，逐字节比较的是 `DynamixelIo` 里的 `StaleImuTracker`，25 帧是告警阈值；B 路线 IMU 线程有自己的帧序号，改成"序号没变"判；`imu_ready` 还应看 BNO085 报告的 accuracy 字段。
- 100 Hz 采样 / 50 Hz 控制环：控制环每 tick 取最新一帧，IMU 线程只做"写最新"，不要平均两帧四元数。
- Game RV 没有磁力计，航向会漂，主控里 `odometry.update` 用了四元数，漂移会进里程计。官方 SFLP 一样漂，不是新问题。
- I2C：主板 i2c3 在官方 HAT 上还挂着 ToF、音频 codec、头部 BMI088，`tofd` 开机往上灌固件。我们不打 HAT，这条总线是空的，但 `tofd` 仍会去探。BNO085 重度拉低 SCL（clock stretching），RK3566 的 I2C 控制器对此不算友好：**接上后先跑 10 分钟 100 Hz 读，记抖动和丢帧**；不行改 BNO085 的 UART-RVC 模式（100 Hz 固定输出，主板多占一路串口）。

方案 A（小板挂总线）：

- rustypot 的 sync_read 严格按 ID 列表顺序逐包收、校验 ID，乱序整 tick 作废。飞特舵机在 sync_read 里是"等前一个答完再答"还是定时答，手册没写：台架先把一个不存在的 ID 放在列表最前面看 15 颗怎么反应，再用逻辑分析仪量小板的应答延迟（§4.2 的 < 100 µs）。
- 固件的协议识别：第一包校验通过即锁定，**运行中不自动解锁**。原稿"连续 100 包失败重判"在总线噪声下会让小板哑 2 s，主控 3 tick 没读数就 hold。

### 3.6 开机序列的映射

```text
FeetechIo::open(port)        Sts3215Controller::new().with_protocol_v1().with_serial_port(1 Mbps, 30 ms)
missing_servos()             ping 15 个，同 XL330 版
adopt_replacement(id)        出厂 ID 1、1 Mbps，不用切波特率：解锁 lock → 写 ID → 加锁 → check_registers_of → 0x08 重启 → 等 ≥ 1 s → ping 新 ID（验证 ID 过了复位）
check_registers()            先读 0–4（固件版本、END 字节序）和 18 相位记日志，断言 END 2 = 0；相位的 BIT2 定速度单位、BIT3 定"速度 0"的含义、BIT0/BIT7 定方向
                             断言：baud 6 = 0 · mode 33 = 4 · 应答级别 8 = 1（出厂就是 1）· 保护参数（19/28/34/36）= FD 里设的值
                             不一致：baud 解锁后写回（同 XL330 版"纠正并计数"）；
                             模式、应答级别、保护参数只告警不改：改错模式会把 15 颗一起改坏，宁可停下来让人看
                             应答级别必须是 1：手册原文"0：除读指令与 PING 外不返回应答包"，rustypot 的 write() 要等状态包，级别 0 下每笔写超时 30 ms
init                         set_torque(true) → set_gain（§3.3，锁着写 P）→ interpolate_to 同前
                             41 加速度 / 46 速度是 SRAM，上电就是 0 / 最大，不写；"46 = 0 是最大"还取决于相位 BIT3，写了反而可能变成"停止"
```

### 3.7 方向和零位

XL330 版没有按关节的方向表，2048 就是零，方向靠舵机装的朝向跟原版一致。飞特：

- 零位：装机时用 FD「中位校准」把直立姿态定成 2048（[调试记录第 9 步](../调试记录.md)），跟 XL330 的 homing 等价。
- 方向：**台架上逐颗验证**，拉到 +30° 看关节往哪边走。如果 STS 的正方向跟 XL330 相反，`[bus.feetech] direction = [±1; 15]`，后端读写时乘上；默认全 +1。

## 4. 小板固件（方案 A · `imu_to_dxl`）

方案 A 的板子（[`hardware/imu_to_dxl/`](../hardware/imu_to_dxl/)）现在是一块通了电的裸板，**固件从零写**。它的工作就一句话：**在舵机总线上冒充一个 ID 200 的舵机，主控读它就回 IMU 数据。** 官方对这块板的全部要求都在 `duck-control/src/imu.rs` 和 `bus.rs` 里，抄下来：

> 📄 **固件实现规格单独成文**：[`hardware/imu_to_dxl/总线协议.md`](../hardware/imu_to_dxl/总线协议.md)
> —— 逐字节块定义、时序数值（含哪些是手册、哪些是推断）、多从机排队规则、上电时序、
> 主控的四条有效性判据、冻结检测带来的两条固件禁令、测试向量、验收清单。
> 配套工具 [`tools/imu200/`](../tools/imu200/)：假小板、向量生成、真板子 13 项检查。

### 4.1 主控对 ID 200 的全部要求

| 项               | 官方 XL330 版（Dynamixel 2.0）                                                                                                    | 我们的飞特版                                                                                                          |
| ---------------- | --------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| 什么时候被问     | 每 tick 一次`sync_read`，ID 列表 `[200, 20..24, 30..34, 10..14]`，地址 124，长度 12                                           | 同一条`sync_read`，ID 列表前面插 200，**地址 56，长度 15**（跟舵机一样的地址，板子自己把 IMU 数据映射到这段） |
| 回什么           | 12 字节：`gyro x/y/z` 各 i16 LE，±500 dps 量程、17.5 mdps/LSB；`quat x/y/z` 各 IEEE 半精度，w 由主控算                       | 同样 12 字节放在前面，后 3 字节：采样计数 + 状态位，凑满 15                                                           |
| 不答的后果       | `sync_read` 等所有 ID，一个不回整条事务失败，**主控这个 tick 就没有传感器数据**                                           | 同                                                                                                                    |
| 其它指令         | 运行时对它**只有 sync_read**：`robotctl` 不碰总线，`missing_servos` / `check_registers` 只查 15 颗舵机的 ID，不查 200 | 同；PING / READ 是给 FD 软件和 URT-2 用的                                                                             |
| 零值含义         | 四元数全 0 = SFLP 还没出数，主控沿用上一帧，不算 ready                                                                            | 同                                                                                                                    |
| 安装方向         | `SflpDecoder::DEFAULT_MOUNT` = 绕 Y 转 +90°，躯干 = `[+raw_z, +raw_y, −raw_x]`                                              | 板子装的朝向要跟原版一致，否则改主控的 mount 四元数                                                                   |
| 上电后多久要有数 | 主控数到 25 帧有效四元数才算`ready`；`decode` 每 tick 一次，即 **0.5 s @ 50 Hz**                                        | 同                                                                                                                    |

关键点：**主控从不写这块板，也不给它配参数**，固件把自己的行为写死就行。

### 4.2 固件模块

```text
imu_to_dxl 固件（STM32G031F8P6，64 KB Flash / 8 KB RAM）
  ├ bus/        USART2 1 Mbps（PA2/PA3），硬件 DE（PA1，CR3.DEP=1 低有效），RX_EN（PB7）
  │   ├ rx      DMA 环形缓冲 + 空闲中断切包
  │   ├ parser  两套协议自动识别（README 第 4 条设计）：
  │   │           FF FF FD 00 … CRC16  → Dynamixel 2.0
  │   │           FF FF ID LEN … CHK   → 飞特（LEN 永远 ≥ 2，无歧义）
  │   │         第一包校验通过即锁定，运行中不自动解锁（见 §3.5 补充）
  │   ├ handler PING → 状态包；READ / SYNC_READ → 从寄存器表取；WRITE → 只认 ID 一项，其余 ACK 不改
  │   └ tx      发送期间 PB7 拉低关接收（或留着，按发送长度丢回显），发完再开
  ├ imu/        LSM6DSV16X，SPI 四线（PA4–PA7）+ INT1（PA0）
  │   ├ init    加速度 ±4 g、陀螺 ±500 dps、ODR 480 Hz；SFLP 游戏旋转向量 120 Hz 开
  │   ├ isr     INT1 数据就绪 → 读 FIFO / 直读，取 gyro 原始值 + SFLP 四元数（芯片本来就出半精度）
  │   └ block   组 12 字节块：gyro i16×3 + quat 半精度 ×3，原子替换（总线中断随时可能来读）
  ├ regs/       寄存器表：一张 128 字节的镜像
  │              Dynamixel 视图：0 型号(=自定义)，6 固件版本，7 ID(200)，8 波特率，124..135 IMU 块，136..143 诊断
  │              飞特视图：    3 型号，5 ID(200)，6 波特率(0)，56..70 IMU 块 + 计数 + 状态
  │              两个视图指向同一块内存，只是地址不同
  ├ clock/      默认 HSI16；X1 已实贴，测通信误码后可切 HSE 旁路；或用定时器捕获主机比特周期反调 HSITRIM
  └ diag/       RTT 日志（J3 的 SWD），计数：收包 / 校验错 / 应答 / 超时
```

时序要求：1 Mbps 下一个字节 10 µs，`sync_read` 里板子排第一个，收完指令到开始应答控制在 **< 100 µs**（飞特舵机自己大约 20–50 µs）；应答 15 字节数据 + 6 字节包头尾 ≈ 210 µs。中断里做，主循环不参与。

## 6. 待查清单（动代码前要确认的，按决定性排序）

1. **寄存器底账**：FD「编程」页把一颗 HD-1910 的 0–90 全部导出存进仓库，§2 的表逐行对：65 status 位定义、69 电流单位、41 加速度单位、8 应答级别出厂值。
2. **运行模式**：出厂 4 是不是就是我们要跑的；模式 4 和 0 下 P/D 的响应差别。
3. **锁着写 P**：lock=1 时写 21，响应是否立即变、重启是否回原值。决定 §3.3 走哪条。
4. **0x08 重启**：备用舵机上发，1 s 后 ping 通、ID 和 EEPROM 保留、65 清零、扭矩关、锁着写的 P 是否回到 EEPROM 值；HD-1910 的固件版本（地址 0/1）支不支持。0x0A 已由手册定性为清圈数，不用测。
5. ~~应答级别 8 出厂值~~ 手册：初始值 1。只剩确认 HD-1910 没被 FD 改过。
6. **sync_read 应答顺序**：不存在的 ID 排首位时 15 颗的行为。
7. 位置寄存器第 15 位在舵机模式下会不会置 1；速度、电流寄存器的符号位。
8. 方向约定（§3.7）。
9. ~~字节序~~ 手册：磁编码系列小端，地址 2 END = 0 可在线断言。
10. 方案 B：BNO085 在 i2c 上 100 Hz 的抖动和丢帧。
11. **半双工回显**：rustypot 收状态包是定长 `read_exact`，不扫包头、不丢回显。官方 HAT 是三态缓冲自动换向，我们走 URT-2 或 ST/SC 转接板，若 RX 常通，每笔事务第一包就是自己的指令，整条总线"不通"，现象像接线错。台架 1b 先验。
12. 台架供电：`battery_empty_shutdown` 默认开，总线电压 ≤ 6.6 V 就坐下关机；HD-1910 有 6 V 档，台架电源 ≥ 7 V 或先关这项。
13. **相位 18 的出厂值**：BIT2（速度单位 1 步/秒还是 50 步/秒）、BIT3（速度 0 是停还是最快）、BIT0/BIT7（方向）。§3.2 的速度系数按它选。

## 8. 评审后补的几件事

### 8.1 构建和部署

fork 的编译产物怎么上板：官方是 `cargo board` / `xtask package` 出 `.deb`，`updater` 只装 `/etc/robot/trusted_keys/` 里的密钥签过的包。`scripts/dev-push.sh` 走开发路径，但它要 **私钥** `~/.duck-keys/team.dev.key`，仓库里只有公钥 `deploy/dev-key/team.dev.pub`，Pollen 的私钥我们拿不到。做法：自己生成一对密钥，公钥放板子 `/etc/robot/trusted_keys/` 并开 `allow_dev_keys = true`，`DUCK_DEV_SECRET_KEY` 指向自己的私钥。写代码前先把"自编的 robotd 能装上并替换 0.13.0"走通，是台架第 9 项的前置。

### 8.2 跟策略 / 训练的关系

- 观测向量 20..34 是关节速度：速度单位换算错一个常数，策略不报错，只会"走得难看"。台架第 5 项要先过。
- `voltage_adapt` 按 XL330 的电压—力矩关系缩放动作，飞特上先关掉或重标。
- 官方 ONNX 是在 XL330（0.52 N·m）上训的；HD-1910 减速比 320:1、1.47 N·m，动力学不同，**大概率不能直接走**。台架 0–9 只验通信，11 验站立，"走"要等重训。

### 8.3 失败模式在 `robotctl health` 里长什么样

| 故障                | 表现                                      |
| ------------------- | ----------------------------------------- |
| 单颗不应答          | sync_read 整条失败，bus 红，missing N     |
| 过载 / 过热锁住     | 65 status 有位，位置不跟随，§3.4 恢复    |
| EEPROM 锁着纠正失败 | 每次开机报 corrected 但不生效             |
| 应答级别 0          | 每次写 30 ms 超时，init 花 1 s 以上并报错 |
| 模式错              | 能通信但位置指令没反应或行为怪            |
| IMU 冻结            | 25 帧相同 → imu stale，跌倒检测停        |
| I2C 挂死（方案 B）  | IMU 线程读超时，序号不动 → stale         |
