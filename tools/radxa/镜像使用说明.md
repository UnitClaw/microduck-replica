# Radxa Zero 3W · 能开机的 Armbian 卡（镜像使用说明）

> **2026-10-21：9 月的两个底包镜像（20260920、20260929）已从 Releases 撤下**，太旧了。要现成的卡请用[复刻镜像](https://github.com/UnitClaw/microduck-replica/releases/latest)：烧了就能用，带主程序、走路模型和 Studio。这个目录的做卡脚本保留，自己做卡照旧可用；下面提到那两个 Release 的地方只是历史记录。

这张镜像解决此前本机遇到的一件事：**所测 Armbian 官方镜像在 Radxa Zero 3W V1.12 上启动失败**（无法登录，局域网里找不到），
换上瑞莎自家的引导程序后能够启动。保留 Armbian 官方内核和系统软件包，调整引导及必要的启动、登录和网络配置。

公开镜像**不带 WiFi 名和密码**，首次启动先等约 2~3 分钟，再通过 USB 串口登录、配置网络。等待时间和绿灯状态不能代替实际登录验证。

- 适用：**Radxa Zero 3W V1.12**（2024-11 以后出厂、AIC8800D80 WiFi 那批），别的批次见下面第 6 节
- 底包：Armbian 26.2.1 Trixie vendor 内核 6.1.115 minimal（官方原版）
- 为什么会这样、怎么定位的：[踩坑记录](../../踩坑记录.md#软件)

> 2026-09-28 摄像头进展：调整排线方向/接触后，瑞莎官方 B1 已识别 IMX219 并完成 40 帧 1920×1080 短测；准备换回本项目镜像复测，尚不能把官方系统的结果当成本镜像的摄像头验收。见[接线图与完整记录](摄像头调试记录-20260928.md)。绿灯双闪可为正常 `heartbeat`，不能单独用来判断启动失败。

> **2026-09-28 联网勘误：** 9 月 20 日的做卡脚本遗漏了 `wlan0` 的 DHCP 配置。保存 WiFi 名和密码只完成认证配置，默认 netplan 仅覆盖有线网卡。脚本现已补上；旧卡按第 4 节补配置即可，不必仅为此重新烧录。Release 附件 `armbian-26.2.1-zero3w-v1.12-bootfix-20260920.img.xz` 仍为原文件，SHA256 不变，**没有包含本次 DHCP 修复**；卡内 `/root/先连WiFi.txt` 也是旧说明，请以本文为准。本机修复后的个人镜像已实测取得 DHCP 地址并通过 SSH 登录，`networkctl` 确认使用新增配置；这不等于公开镜像已替换，也不代表所有失联问题都已解决。见[联网与 HAT 实测记录](联网与HAT调试记录-20260928.md)。

> **2026-09-29 更新：** 首次登录应为 `root / 1234`，见第 3 节。另提供独立的 DHCP 修复候选镜像，保留旧版；候选版已离线核查 DHCP、首登机制、文件差异及隐私项，**尚未对这一新产物烧卡实测**。它仍是基础系统，没有安装机器人运行时、网页调试台或策略。

## 1. 跟官方 Armbian 镜像的区别

主要改动如下（其中 DHCP 是 2026-09-28 的脚本修复，旧 Release 镜像需手动补上）：

| 改了什么 | 为什么 |
|---|---|
| 引导程序换成瑞莎 `u-boot-rk2410`（`idbloader.img` @扇区 64、`u-boot.itb` @扇区 16384） | 此前本机的引导兼容性问题通过替换后解决；具体包版本及校验值锁定在制卡脚本中 |
| 写 `/boot/extlinux/extlinux.conf` | 瑞莎 U-Boot 走 extlinux，不读 Armbian 的 `boot.scr` |
| 挂 `uart2-m0` 和 `dwc3-peripheral` 两个 overlay，内核控制台放 `tty1` | 前者出 `/dev/ttyS2`（40 脚上的串口，接舵机用），后者让 OTG 口插电脑变成串口；内核日志不再往舵机总线上打 |
| 开 `g_serial` + `ttyGS0` 登录控制台，关掉 `ttyS2` / `ttyFIQ0` 上的登录控制台 | 插电脑就能登录，没网也能救；`agetty` 占着 `ttyS2` 舵机怎么都不通 |
| 配置无线认证和 `wlan0` DHCP | 带 Wi-Fi 版预置认证信息；两种制卡模式都写入 `25-wlan0.network`，补足默认 netplan 未覆盖无线网卡的问题。旧版镜像需手动补配 |

## 3. 第一次开机

1. 卡插板子，**`5V IN / USB_OTG`（USB 2.0）口**用数据线插电脑，由电脑 USB 供电。另一个 **USB 3.0 Host** 口用于接 URT-2、U 盘等外设，不能用来让电脑识别本机的 USB 串口。
2. 等约 2~3 分钟，正常启动并加载 USB gadget 后，电脑设备管理器应出现 **COM 口**（USB 串口设备）。用 PuTTY / MobaXterm / 串口助手打开，**115200 8N1**，回车。若没有 COM 口，先检查接口、数据线和供电，不能只凭绿灯判断系统或镜像损坏。
3. **第一次登录用 `root` / `1234`。** 随后按 Armbian 向导完成初始化；如出现 shell 选项，可选 `bash`。向导读取镜像内的预设，才会将 root 密码改成 `duck1234`，并创建 `duck` / `duck1234`。看到 `duck` 已创建的提示后再切换普通用户；不要在第一次认证时使用 `duck`。
4. **完成向导后立即改密码**。仍在 root 终端时执行：

```bash
passwd            # 改 root 的
passwd duck       # 改 duck 的
```

以后使用 `duck` 登录。若已在 `duck` 终端，改自己的密码用 `passwd`，改 root 密码用 `sudo passwd root`。自己制卡且修改过 `card.conf` 的用户，以自己的预设为准。

**为什么旧说明登录不了？** 2026-09-29 对 9 月 20 日公开镜像只读核实：原始 `/etc/passwd` 没有 `duck`，root 的密码匹配 `1234`；`PRESET_ROOT_PASSWORD` 和 `PRESET_USER_NAME` 由登录后的 `/etc/profile.d/armbian-check-first-login.sh` 调用首次登录向导才应用，不是首次认证凭据。此前写“首次 `duck / duck1234`，root 密码相同”有误。若向导中途退出，root 密码可能已经改变，而 `duck` 仍未创建；用已经设置的 root 密码重新登录完成向导，或先在现有 root 终端执行 `id duck` 检查，不要为此盲目重刷。

串口里看不到启动日志是正常的：内核日志被放到 `tty1` 了，串口只给登录用。

### 旧版卡：重新生成 SSH 主机密钥

9 月 20 日公开镜像携带了预生成的 SSH 主机密钥；克隆出来的卡会共享它们。9 月 29 日候选镜像已移除这些文件，保留空 `machine-id`，并确认原系统的 `sshd-keygen.service` 已启用，首次启动会执行 `ssh-keygen -A`。这是静态机制核查，新候选产物尚未烧卡验证。

已经烧过旧版的卡，可在 **USB 串口或本地终端**完成首登后执行下面的命令，重新生成本机密钥，不需要重刷：

```bash
sudo rm -f /etc/ssh/ssh_host_{rsa,ecdsa,ed25519}_key{,.pub}
sudo ssh-keygen -A
sudo systemctl restart ssh
sudo ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub
```

主机指纹会改变。下次电脑 SSH 若提示旧指纹不一致，先与上面在主板本地显示的指纹核对，再在电脑用 `ssh-keygen -R 主板IP` 删除这个地址的旧记录并重新连接。

**已经通过 HAT / 40 针供电时：** 本节的普通 USB 数据线接法不要直接叠加使用。
Radxa Zero 3W V1.12 官方原理图第 20、22 页中，40 针的 2/4 脚与 OTG 口的
VBUS 都接在 `+5V_INPUT` 同一网络，普通 USB 数据线会把电脑的 5V 和 HAT 的
5V 输出并在一起。调试 HAT 供电时优先用 WiFi + SSH 登录；需要 USB 串口时，
先正常关机并断开 HAT 输入，再切换到 USB 单独供电。

勘误（2026-09-28）：此前本节把“USB 3.0 口”写成电脑连接口，现已按
[瑞莎官方接口说明](https://docs.radxa.com/en/zero/zero3)及 V1.12 原理图纠正。

## 4. 连 WiFi

以下适用于本项目的 Armbian 基础镜像，使用 `wpa_supplicant` + `systemd-networkd`。如果后续已经迁移到 NetworkManager，请通过它修改连接，不要再同时启用另一套无线管理服务。基础镜像没有安装 NetworkManager / `nmtui`。

本镜像的无线凭据不在 netplan 中，不能直接照搬上游 `migrate-network.sh` 的网络迁移步骤；迁移前需处理凭据导入、旧服务退出和失联恢复，见[目录说明](README.md)。

### 已经填过 WiFi，只补 DHCP

确认 WiFi 名和密码正确后，通过 USB 串口或本地终端登录，执行：

```bash
sudo mkdir -p /etc/systemd/network
sudo tee /etc/systemd/network/25-wlan0.network >/dev/null <<'NETWORK'
[Match]
Name=wlan0

[Network]
DHCP=ipv4
NETWORK
sudo chmod 644 /etc/systemd/network/25-wlan0.network
sudo systemctl enable --now systemd-networkd wpa_supplicant@wlan0
sudo networkctl reload
sudo networkctl reconfigure wlan0
```

这一步保留原来的 WiFi 认证配置。随后按下面“检查连接”核实结果；仅补 DHCP 不会修复密码错误、无线驱动或供电问题。

### 第一次联网，或者更换 WiFi

通过 USB 串口或本地终端操作。下面会替换已有 WiFi 配置；重启无线服务会断开当前无线 SSH。把示例里的 WiFi 名和密码换成自己的，`country` 填实际所在地的两字母国家代码（中国为 `CN`）：

```bash
sudo mkdir -p /etc/wpa_supplicant /etc/systemd/network
sudo tee /etc/wpa_supplicant/wpa_supplicant-wlan0.conf >/dev/null <<'CONF'
ctrl_interface=DIR=/run/wpa_supplicant GROUP=netdev
update_config=1
country=CN

network={
    ssid="你的WiFi名"
    psk="你的WiFi密码"
    key_mgmt=WPA-PSK
    pairwise=CCMP
    ieee80211w=0
    scan_ssid=1
    priority=10
}
CONF
sudo chmod 600 /etc/wpa_supplicant/wpa_supplicant-wlan0.conf
sudo tee /etc/systemd/network/25-wlan0.network >/dev/null <<'NETWORK'
[Match]
Name=wlan0

[Network]
DHCP=ipv4
NETWORK
sudo chmod 644 /etc/systemd/network/25-wlan0.network
sudo systemctl enable --now systemd-networkd
sudo systemctl enable wpa_supplicant@wlan0
sudo systemctl restart wpa_supplicant@wlan0
sudo networkctl reload
sudo networkctl reconfigure wlan0
```

这里显式重启无线服务，让改过的 WiFi 名和密码生效；单独运行 `enable --now` 不会让已经运行的服务重读配置。

### 检查连接

等待约 30 秒，再执行：

```bash
sudo wpa_cli -i wlan0 status   # 认证成功应有 wpa_state=COMPLETED
ip -4 a show wlan0            # 看有没有拿到 IPv4 地址
ip -4 route                   # 看有没有默认路由
networkctl status wlan0       # 看匹配的网络配置及 DHCP 状态
```

`wpa_supplicant` 负责连接无线网络，`systemd-networkd` 根据 `25-wlan0.network` 申请 IPv4 地址。
本镜像自带的 `/etc/netplan/10-dhcp-all-interfaces.yaml` 只匹配 `e*`、`lan[0-9]*` 和 `wan[0-9]*`，**不会给 wlan0 获取地址**。

上面的 `WPA-PSK` / `CCMP` / `ieee80211w=0` 沿用此前 AIC8800 调试采用的 WPA2 兼容配置，要求路由器允许 WPA2-PSK / AES，不能用于只允许 WPA3 或强制 PMF 的网络。混合模式握手失败时可先用 WPA2 网络对照测试；不要把所有认证失败都归因于同一种加密算法。

排查顺序：找不到 `wlan0` 先查设备/驱动；认证不是 `COMPLETED` 先查 WiFi 名、密码、信号和路由器模式；认证完成但无 IPv4，再查 DHCP 配置、网络管理服务和路由器地址分配。需要进一步排查时查看：

```bash
sudo journalctl -b -u wpa_supplicant@wlan0 -u systemd-networkd --no-pager -n 80
```

分享日志前遮掉自己的 WiFi 名等个人信息，不要上传包含密码的认证配置文件。

连上以后路由器里找 `radxa-zero3`，之后 `ssh duck@板子IP` 就行，不用再插串口。

**换电脑不需要重刷系统：** 电脑和主板在同一个可互通的局域网即可；访客网络/AP 隔离可能阻止互访。**换 WiFi 要改连接配置：** 主板不会自动知道新密码，照本节重配即可，也不需要重刷。DHCP 分配的 IP 可能变化，要重新查地址，不能一直沿用旧 IP。

嫌麻烦不想每次手动连：用仓库里的做卡脚本，烧卡前就把 WiFi 写进去 ——
[`build-armbian-card.sh`](build-armbian-card.sh)，`card.conf` 里填上 WiFi 名和密码，自己生成一张带网的卡（这张公开镜像就是用同一个脚本、WiFi 留空做的）。

## 5. 舵机串口

`/dev/ttyS2` 已经准备好了（40 脚的 8 号 TX、10 号 RX），登录控制台和内核日志都从上面拿掉了。

注意：**RK3566 的 UART 是全双工 3.3 V 两根线，飞特 / Dynamixel 总线是单线半双工**，中间要加三态缓冲或者转接板，直接飞线是收不到应答的。见[踩坑记录](../../踩坑记录.md#飞线不打-hat-时)。

## 6. 如果你的板子不是这一批

Zero 3W 出过好几批，板子上的 WiFi 模块和设备树都换过。判断方法：这张卡烧进去进不了系统，但**瑞莎官方镜像能起**。

### V1.12J（2026-09 这批，AIC8800DS2）—— 已经有人跑通了

群友报告在其板子上使用 **B1 的引导 + B1 的 DTB + Armbian 6.1.115 内核 + Trixie 系统** 跑通，光换引导还不够。这是特定板卡与镜像组合的经验，不能仅凭两边都是 6.1 vendor 内核就认定 DTB 可以通用；本项目尚未独立验证该组合。先排除联网配置和接线问题，再考虑下面的引导/设备树对照。

三步（`/dev/sdX` = 烧好瑞莎 B1 官方镜像的卡，`/dev/sdY` = 烧好这张 Armbian 卡的卡，**别搞错盘**）：

```bash
# 1) 扒 B1 的引导，写进 Armbian 卡
sudo dd if=/dev/sdX of=idbloader.img bs=512 skip=64    count=16320
sudo dd if=/dev/sdX of=u-boot.itb    bs=512 skip=16384 count=16384
sudo dd if=idbloader.img of=/dev/sdY bs=512 seek=64    conv=notrunc
sudo dd if=u-boot.itb    of=/dev/sdY bs=512 seek=16384 conv=notrunc

# 2) 把 B1 的 DTB 拷到 Armbian 卡（文件名以 B1 镜像里的为准，找 Zero 3W 那份）
sudo mount /dev/sdX1 /mnt/b1 ; sudo mount /dev/sdY1 /mnt/armbian
ls /mnt/b1/boot/dtbs/*/rockchip/ | grep -i zero3
sudo cp /mnt/b1/boot/dtbs/*/rockchip/rk3566-radxa-zero3.dtb /mnt/armbian/boot/dtb/rockchip/rk3566-radxa-zero3-b1.dtb

# 3) extlinux 的 fdt 指向它
sudo sed -i 's|^  fdt .*|  fdt /boot/dtb/rockchip/rk3566-radxa-zero3-b1.dtb|' /mnt/armbian/boot/extlinux/extlinux.conf
sync; sudo umount /mnt/b1 /mnt/armbian
```

换成瑞莎的 DTB 以后**验两件事**，因为 overlay 是 Armbian 那边的，节点对不对得上要看：

- `ls /dev/ttyS2` 在不在（40 脚的舵机串口，`uart2-m0` overlay 起没起作用）
- 板子插电脑还有没有 COM 口（`dwc3-peripheral` overlay）

对不上就把 `fdtoverlays` 那行去掉，改用瑞莎自己的 overlay（B1 镜像的 `/boot/dtbo/` 里），或者直接在瑞莎的 DTB 上改。

### 其它批次

可用自己能启动的官方镜像做对照，但移植引导、DTB 与 overlay 前须核对板卡和内核兼容性，不能保证跨批次可用。
还是不行就接 40 脚的调试串口（3.3 V USB-TTL，1500000）看 U-Boot 输出，或者在
[issue](https://github.com/UnitClaw/microduck-replica/issues) 里说清楚板子版本、WiFi 模块、卡在哪一步。

### 已知问题

- **V1.12J 冷启动插着 HDMI 起不来**（群友反馈，按上面三步改好之前的状态）。如果碰到：先不插 HDMI 冷启动，
  起来后再插；或者在 extlinux 的 `append` 末尾加 `video=HDMI-A-1:d` 关掉 HDMI 输出。
  我们这张镜像的内核控制台是 `console=tty1`（走显示），跟这个有关。
